# Agent Instructions for Agustín Juárez Portfolio

## Project Overview

This is an **Astro (static output) + React islands** portfolio website for a full-stack developer. It uses Tailwind CSS 4, framer-motion for animations, react-i18next for internationalization (Spanish/English), and is deployed on Vercel. The project includes both frontend (src/) and serverless API endpoints (api/).

**Why Astro:** the site is statically generated per route — every page ships route-specific `<title>`/meta/canonical/hreflang/JSON-LD in its HTML (SEO requirement). React components are hydrated islands (`client:load`), so they prerender to real HTML AND stay interactive.

## Architecture

### Routing & i18n

- **Spanish is the default locale** and stays at root URLs (`/`, `/proyectos`, `/sobremi`, `/educacion`, `/contacto`, `/experiencias/:slug`, `/proyectos/:slug`).
- **English lives under `/en/...`** with translated slugs: `/en/`, `/en/projects`, `/en/about`, `/en/education`, `/en/contact`, `/en/experiences/:slug`, `/en/projects/:slug`.
- `src/pages/` holds `.astro` route files (ES at root, EN under `src/pages/en/`). Dynamic routes use `getStaticPaths()` (see `src/lib/staticPaths.js`).
- `src/i18n/routes.js` is the **single source of truth** for route pairs (`ROUTES`, `routeFor`, `projectPath`, `experiencePath`). Every page declares its `esPath`/`enPath` pair — used for both `hreflang` and the language switcher.
- `src/i18n/index.js` exports `createI18n(lng)` — a per-locale i18next instance (no browser language detection; the URL decides the language).
- `src/i18n/t.js` is a synchronous `t(locale, key)` helper for `.astro` frontmatter.
- `src/i18n/LocaleContext.jsx` exposes `useLocale()` / `useLocalizedRoutes()` to hydrated components.

### React islands pattern

- `src/components/PageShell.jsx` wraps every page: `I18nextProvider` + `LocaleContext` + `ThemeProvider` + NavBar/main/Footer + DotFieldBackground.
- **Never** pass a React component as `<Astro slot>` child of a hydrated component — context does not cross that boundary during prerender. Instead each view has a wrapper in `src/views/pages/` (e.g. `HomePage.jsx`) that composes `PageShell` + view inside the same React tree. `.astro` files render exactly ONE island: `<HomePage ... client:load />`.
- View components live in `src/views/` (former `src/pages/` React pages). They take data like `slug` via props, not router hooks.
- **No react-router, no react-helmet.** Navigation is plain `<a href>` with localized paths from `useLocalizedRoutes()`. Metadata is static in `BaseLayout.astro`.

### SEO layer

- `src/layouts/BaseLayout.astro` is the only `<head>`: title/description (from `seo.*` i18n keys or props), canonical (`https://www.agustinjz.dev`), `hreflang` (es/en/x-default), Open Graph, Twitter, JSON-LD (`WebSite` + `Person`), theme init script, SpeedInsights.
- `noindex` prop renders `noindex,follow` (used by `404.astro`).
- Sitemap is generated by `@astrojs/sitemap` → `dist/sitemap-index.xml`; `public/robots.txt` points there. Do NOT hand-maintain a sitemap.
- Canonical host is always `https://www.agustinjz.dev` (the apex redirects here). `precios.agustinjz.dev` is a separate project — never rewrite it.
- `public/og-image.jpg` is the real 1200×630 social card.

## Code Style Guidelines

### File Naming Conventions

| Type | Convention | Example |
|------|------------|---------|
| Components | PascalCase | `NavBar.jsx`, `Hero.jsx` |
| Views (React page content) | PascalCase | `src/views/Proyectos.jsx` |
| Page wrappers (island entry) | PascalCase + `Page` | `src/views/pages/HomePage.jsx` |
| Astro routes | lowercase | `src/pages/sobremi.astro`, `src/pages/en/about.astro` |
| Hooks | camelCase + `use` prefix | `useAccentColors.jsx` |
| i18n | `index.js` + `locales/` folder | `i18n/index.js` |

### Directory Structure
```
src/
  pages/           # .astro routes (ES at root, EN under en/)
  layouts/         # BaseLayout.astro (head + SEO)
  views/           # React page bodies (no routing logic)
    pages/         # Page wrappers: PageShell + view (one per page)
  components/      # Reusable UI components
  hooks/           # Custom React hooks
  lib/             # Shared build-time helpers (staticPaths)
  data/            # projects.js, experiences.js (route/slugs source)
  i18n/            # locales + routes map + LocaleContext
  styles/          # globals.css (Tailwind 4 via @tailwindcss/vite)
api/               # Vercel serverless functions
```

### Component Structure

```jsx
// 1. External library imports (framer-motion, icons)
// 2. Internal imports (hooks, i18n, ui)
// 3. Constants
// 4. Main function component

import { motion } from "framer-motion";
import { useAccentColors } from "../hooks/useAccentColors";
import { useTranslation } from "react-i18next";
import { useLocalizedRoutes } from "../i18n/LocaleContext.jsx";

export default function ComponentName() {
  const { accentColor } = useAccentColors();
  const { t } = useTranslation();
  const { routeFor } = useLocalizedRoutes();

  return <a href={routeFor("projects")}>{t("navbar.projects")}</a>;
}
```

### Import Conventions

- **Icons**: `react-icons/*` or `lucide-react`
- **i18n**: `useTranslation` from `react-i18next`; locale routing via `useLocalizedRoutes()`
- **Alias**: `@/` maps to `src/` (configured in `astro.config.mjs` vite alias + `tsconfig.json`/`jsconfig.json` paths)
- **Internal components**: Relative imports with `.jsx` extension

### Styling Patterns

- Tailwind CSS 4 utilities; `tw-animate-css` for animations; CSS vars `--font-display`/`--font-body`
- Theme via `ThemeProvider` (`useTheme`) — dark/light/system, persisted in `localStorage["theme"]`; `BaseLayout` has an inline anti-FOUC script that must stay in sync with `src/hooks/themeUtils.js` storage keys.
- Framer Motion: `const MotionDiv = motion.div;` — respect `useReducedMotion`.

### Adding a new page

1. Create the React view in `src/views/` (pure content, `useTranslation` for text).
2. Create a wrapper in `src/views/pages/XPage.jsx`: `<PageShell {...props}><X /></PageShell>`.
3. Add the route pair to `src/i18n/routes.js` (`ROUTES`).
4. Create `src/pages/x.astro` (ES) and `src/pages/en/y.astro` (EN) rendering `<XPage locale currentPath={Astro.url.pathname} paths={{es,en}} client:load />` inside `<BaseLayout seoKey=...>`.
5. Add `seo.<key>.title`/`description` keys to BOTH `locales/es.json` and `locales/en.json`.
6. NavBar `LINKS` entry if it belongs in the nav.

### SSR safety

Everything inside an island renders on the server during `astro build`. Never touch `window`/`document`/`localStorage` during render — only inside `useEffect` or guarded (`typeof window !== "undefined"`). See existing hooks for the pattern.

### API Routes

- `api/contact.js` stays a Vercel serverless function (`export default handler(req,res)`), env vars `RESEND_API_KEY`, `MAIL_FROM`, `MAIL_TO`. It does NOT run under `astro dev` — test it with `vercel dev` or in production.

### ESLint Configuration

- Standard JSX (no TypeScript)
- React Hooks rules enabled
- `no-unused-vars` ignores variables starting with uppercase
- `dist/`, `api/`, `e2e/` ignored

## Deployment Notes

- Vercel builds `astro build` → static `dist/`; `api/` deploys as functions
- `vercel.json` holds permanent redirects only — NO SPA rewrites (they would break static SEO)
- Public assets: all images are WebP (max 1600px) — keep new assets under ~300KB
- Vercel Speed Insights via `@vercel/speed-insights/astro` in `BaseLayout`
